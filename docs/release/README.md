# ការចេញកំណែ GDM (version)

GDM មានលេខកំណែតែមួយគត់ ដែលរក្សាទុកក្នុង `package.json` និង `[workspace.package]` នៃ `Cargo.toml`។ កម្មវិធី, bridge, extension, installer និង User-Agent ទាំងអស់យកលេខពីទីនោះ។ គ្មាននរណាកែលេខដោយដៃទេ។ មានតែ `scripts/version.mjs` ប៉ុណ្ណោះដែលប្ដូរវា។

## ចេញកំណែថ្មី (ចុចតែម្ដង)

1. GitHub → Actions → **version** → Run workflow (branch `main`)។
2. ជ្រើសប្រភេទ៖
   - **minor**: ចេញធម្មតា (លំនាំដើម) ឧ. 1.0.0 → 1.1.0
   - **patch**: សម្រាប់តែការជួសជុលបន្ទាន់ ឧ. 0.10.0 → 0.10.1
   - **major**: ការផ្លាស់ប្ដូរធំ
3. workflow ជ្រើសលេខបន្ទាប់ដោយខ្លួនឯង រួចធ្វើ commit `release vX.Y.Z` និង tag។ បន្ទាប់មកវាដំណើរការ `release.yml` ដើម្បី build ទាំង ៦ គោលដៅ ហើយបង្កើត release ជា **draft**។ អ្នក publish draft នោះដោយខ្លួនឯង។

## ហេតុអ្វីលេខមិនឡើងលឿនពេក

- លេខប្ដូរតែពេលចុចប៊ូតុងនេះប៉ុណ្ណោះ។ commit, push ឬ build នីមួយៗ មិនប្ដូរលេខទេ។
- លំនាំដើមជា minor ដូច្នេះលេខចុងក្រោយនៅតែ 0។
- workflow បដិសេធ ពេលគ្មានអ្វីថ្មីតាំងពីការចេញលើកមុន។
- workflow បដិសេធ minor/major ដែលចេញក្រោយលើកមុនមិនដល់ ៧ ថ្ងៃ។ patch សម្រាប់ការជួសជុលបន្ទាន់ ចេញបានគ្រប់ពេល។
- ការចុចលើកដំបូងចេញ 1.0.0 ដូចដែលមានស្រាប់ ដោយមិនបូកលេខ។
